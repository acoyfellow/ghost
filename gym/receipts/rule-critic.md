- **F3 late-overlay: truth is timing-dependent.** "1 to 3 s after load, before the click" depends on when the collector clicks. If it clicks at 0.5 s, a "broken" page is actually held, and the page gets dropped or the label stays wrong. Fix: the click fires at a fixed time (say 4 s after load, or after a `data-ready` flag). The generator also states the overlay delay in a header. A screenshot taken before the overlay and a click after it should be an explicit step in the protocol.

- **F9 moving-target: the held condition is ambiguous.** "Moves but its centre stays under the click point" depends on which point counts as the click point. That is the centre at screenshot time. Fix: define the click point as the screenshot-time centre. Define held as the click-time box containing that point, with `hit-is-target` confirmed by the trusted click. Also fix the move timing, as in F3.

- **F9/F3 leak: the facts include both screenshot-time and click-time boxes and the DOM mutations.** A rule that compares the two boxes, or checks for any mutation, solves F9 and F3 trivially. It also hands `dom-rule` a re-check at click time. Fix: say whether every system sees click-time facts. If the candidate does, `dom-rule` must also get a click-time variant as a baseline. If not, drop those facts from the candidate's input.

- **F10 disabled-or-inert: "no click event reaches it" is not a click-miss.** `elementFromPoint` still returns the target inside an inert region or disabled fieldset, so `dom-rule` fails every broken page. That is fine. But the `inert`/`disabled` facts are listed for the train families too, and a rule of "inert or disabled means broken" is a single boolean. Fix: expect F10 to be solved by a one-line check. Make held cases include `disabled` on an unrelated fieldset sibling and `inert` on an ancestor of a different element. Add disabled-looking but live targets, such as `aria-disabled` or a `disabled` class with no attribute.

- **F8 train / F2 train leak into F6, F7 and F3.** Any "the hit element is not the target, and it is fixed or high-z" rule solves F2, F3 and F4, and mostly F6 (the canvas is the hit). `dom-rule` also solves them. Fix: the discrimination check must be per family and mandatory. Pre-register which held-out families `dom-rule` is expected to fail, probably only F3 (overlay timing), F9 and F10. Raise the F6 and F7 difficulty so that the hit element is not obviously an overlay (a canvas with no fixed/high-z styling).

- **F7 shadow-iframe: the truth may be unconfirmable.** For a cross-origin iframe, `elementFromPoint` returns only the iframe host. The collector cannot see inside, so the "hit path" fact does not exist. Fix: restrict to same-origin or `srcdoc` iframes, and open shadow roots only. State this in the rule.

- **F7 label ambiguity: a held page where the iframe or shadow content is merely present near the target.** Because the host element is returned, a "hit is not the target" rule marks it broken. Fix: make held F7 pages put the shadow host or iframe box over the target with its content transparent or not covering, with `pointer-events` unset, so that the host-level hit is the same on broken and held pages. Then only the inner hit path separates them.

- **F5 and F4 held cases look identical to the broken cases at the DOM level.** The truth differs only through `pointer-events`, and the Browser Run collector records `elementFromPoint`, which already respects it. So `dom-rule` solves both. That is fine, but it means F5 is a pass for every system except vision. Fix: state it. Count F5 as a vision-only discriminator, and do not use it to claim the candidate beats `dom-rule`.

- **F1 clean is trivially passed.** It has no broken seeds, so F1 on `broken` is undefined (0/0). F5 has the same problem. Fix: score them as false-positive rate, not F1. Exclude them from F1 pooling, or the 0/0 handling will skew the numbers.

- **Memorisation: seeds 0..49 are fixed and the generator is deterministic.** The candidate sees train-family facts, the `x-ghost-truth` header may be among them, and the generator is a small parameter space. Fix: strip the header from the facts the candidate sees. Draw the seed sets A, B and C from a held-back salt, and give the candidate at most 5 scorer runs against pages it cannot enumerate. Require the rule file's size to be under a fixed limit and to contain no literals taken from page data.

- **Set A/B/C metric is gameable and noisy.** Seeds 0..16 give about 8 broken pages per family and set, so the F1 variance is large, and "worst set vs best set" rewards luck. The deterministic-system claim of "the same result on every set" holds only for the rule. Vision models vary between runs. Fix: run each vision baseline 3 times, take the median, and compute bootstrap CIs. Use 50 seeds per family pooled, with the A/B/C split reported as a secondary check.

- **Real-site gate (condition 3) and spend are loosely specified.** 0.883 is an unexplained threshold, and the 193 pages carry no ground-truth protocol. The $25 budget is not allocated across the vision baselines, 3 sets, and Browser Run clicks. Fix: state how the real-page labels were obtained (a trusted click, same as the gym), and where 0.883 comes from (for example, `ghost-compiled-v1`'s score). Add a per-system spend cap.
